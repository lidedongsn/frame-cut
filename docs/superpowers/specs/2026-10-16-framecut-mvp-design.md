# FrameCut MVP 设计文档

日期：2026-10-16

## 1. 目的与背景

FrameCut 是一个 macOS 原生的 vlog 剪辑工具，对标剪映 Mac 版的核心剪辑体验。

- **为什么做**：剪映常用功能（自动字幕、部分滤镜、高清导出等）需要付费。作者自己剪 vlog 想要一个免费、本地运行、无水印的工具；先自用，打磨好之后做成产品。
- **典型场景**：一段约 3 分钟的 vlog，主要操作是剪辑、裁剪、滤镜、背景音乐、字幕和转场。
- **成功标准**：作者能完全用 FrameCut 替代剪映完成一条 3 分钟 vlog，从新建工程到导出，全程不卡顿、不丢工作。

## 2. 目标、非目标、反目标

### 目标（MVP 必须有）

形成完整闭环：新建工程 → 导入素材 → 剪辑 → 画面处理 → 转场 → 音频 → 字幕 → 自动保存 → 导出。

1. **工程管理**：启动页显示最近项目；可新建、打开、保存工程；工程文件为 `.framecut` 包（文件夹，内含 JSON）。
2. **导入**：视频（mov/mp4/m4v）、图片（jpg/png/heic）、音频（mp3/m4a/wav/aac）。拖入素材面板或使用导入对话框。素材丢失时提示并可重新定位。
3. **时间线**：
   - 轨道：一条主视频轨（片段首尾相接、无空隙，类似剪映主轨）、一条音乐轨、一条字幕轨。
   - 操作：在播放头处分割（⌘B）、删除（Delete）、拖动排序、拖动片段边缘修剪首尾、变速（0.25x–4x，音频变速不变调）。
   - 撤销 / 重做（⌘Z / ⇧⌘Z），覆盖所有编辑操作。
   - 时间线缩放（⌘+ / ⌘-，或捏合）、播放头跟随、点击定位、空格播放 / 暂停。
   - 图片默认时长 3 秒，可修剪。
4. **画面**：
   - 画幅：工程级 16:9、9:16、1:1、4:3、3:4。
   - 单片段变换：缩放、位移、旋转（90° 步进），默认填充（fill）画幅。
   - 滤镜：约 10 个内置风格预设（如清新、暖阳、胶片、黑白、复古、冷调等）＋强度；调节：亮度、对比度、饱和度、色温。可一键应用到全部片段。
5. **转场**：叠化、渐黑、渐白、推移（左右上下）、滑入、擦除、缩放、模糊，共约 8 类；时长 0.2–2 秒；可一键应用到全部交界处。
6. **音频**：
   - 片段原声：音量（0–200%）、静音。
   - 音乐轨：可放多段音乐，位置自由；音量、淡入、淡出；可分割、修剪、删除。
7. **字幕**：
   - 手动添加字幕条；字幕轨上可拖动、修剪时间。
   - 自动识别：对主轨原声做本地语音识别（中文为主，自动检测语言），生成字幕条。完全离线，首次使用下载模型。
   - 校对：字幕列表中逐条修改文字、调整时间。
   - 样式：字体、字号、颜色、描边、背景、垂直位置；默认对全部字幕生效（全局样式）。
8. **预览**：实时预览，所见即所得（预览与导出共用同一渲染管线）。
9. **导出**：分辨率 720p / 1080p / 4K（按画幅计算），帧率 24/25/30/60，编码 H.264 / HEVC；进度条、可取消；完成后可在 Finder 中显示。无水印。
10. **自动保存与恢复**：编辑后自动保存（防抖约 2 秒）；崩溃或强退后重开不丢失工作。

### 非目标（MVP 不做，第二阶段考虑）

贴纸、花字动画、关键帧动画、画中画 / 多视频轨、模板、蒙版、抠像、美颜、配音录制、音频降噪、封面选取、云同步、多语言 UI（仅中文界面）。

### 反目标（技术上能跑但算失败的情况）

- 编辑时界面卡顿（拖动时间线、修剪掉帧明显）。
- 预览与导出效果不一致。
- 丢失用户工作（崩溃 / 退出后丢编辑）。
- 导出带水印或任何付费墙。
- 需要联网才能使用核心功能（模型首次下载除外）。

## 3. 约束

- 平台：仅 macOS 14 及以上，Apple Silicon 优先（基准机 M2 / 16GB）。
- 语言与框架：Swift（Swift 6 编译器，Swift 5 语言模式以降低 AVFoundation 并发适配成本），SwiftUI ＋ 必要处 AppKit，AVFoundation、Metal、Core Text。
- 性能指标（基准机）：1080p 素材预览 30fps 不掉帧；3 分钟 1080p 工程导出 ≤ 实时时长；时间线交互 60fps。
- 依赖最少化：仅字幕识别引入第三方库（WhisperKit，MIT 协议）。
- 分发：暂不考虑 App Store 沙盒；本地运行用 “Sign to Run Locally”。

## 4. 架构（已决定）

### 4.1 模块划分

```
FrameCut.xcodeproj（XcodeGen 生成，project.yml 为准）
└─ App：FrameCut（SwiftUI 界面、窗口、菜单、快捷键）
Packages/FrameCutKit（本地 Swift Package）
├─ FCCore       工程数据模型、编辑命令、撤销重做、工程读写。纯 Swift，不依赖 AVFoundation 渲染
├─ FCEngine     把工程编译成可播放 / 可导出的 AVFoundation 对象；Metal 合成器、滤镜、转场、字幕渲染
├─ FCMedia      素材导入与探测、缩略图、音频波形
└─ FCTranscribe 本地语音识别（WhisperKit 实现，接口抽象可替换）
```

依赖方向：App → FCEngine / FCMedia / FCTranscribe → FCCore。FCCore 不依赖其他模块。

### 4.2 数据模型（FCCore）

所有模型为值类型（struct）、`Codable`，时间用有理数 `Rational`（值/时基，避免浮点误差，可与 `CMTime` 互转）。

- `Project`：id、名称、画幅、帧率、`assets: [MediaAsset]`、`mainTrack: [VideoClip]`、`transitions: [ClipBoundaryID: Transition]`、`musicTrack: [AudioClip]`、`subtitles: [Subtitle]`、`subtitleStyle`、`createdAt / modifiedAt`。
- `MediaAsset`：id、类型（video/image/audio）、原始路径（书签 + 路径）、时长、尺寸、帧率、是否有音轨、旋转信息。
- `VideoClip`：id、assetID、源区间（sourceIn / sourceOut）、速度、音量、静音、变换（缩放、位移、旋转）、滤镜（预设 + 强度 + 调节参数）。
- `Transition`：类型、时长。**挂在两片段交界处**（以后一片段 id 为键），不是独立片段。
- `AudioClip`：id、assetID、时间线起点、源区间、音量、淡入、淡出。
- `Subtitle`：id、起止时间、文字。

**主轨时间计算**：片段顺序排列，片段在时间线上的时长 = 源时长 / 速度。转场采用“重叠”模型：带转场的交界处，后一片段向前与前一片段重叠转场时长，总时长相应缩短；转场时长被限制为不超过相邻两片段各自时长的一半。时间线布局由 FCCore 中的纯函数 `TimelineLayout` 计算，供 UI 与引擎共用。

**编辑命令与撤销**：`EditorStore`（`@Observable`，主线程）持有当前 `Project`，所有修改经由命令方法（split、delete、move、trim、setSpeed…）完成；撤销栈保存 `Project` 快照（值类型，结构共享开销小），上限 100 步。连续拖动类操作（修剪、拖音量）在开始时打一个快照，结束时合并为一步。

**工程文件**：`.framecut` 为包目录：`project.json`（工程）＋ `cache/`（缩略图、波形、识别结果缓存，可删除重建）。素材不复制，引用原路径。工程文件带 `schemaVersion` 字段以便迁移。

### 4.3 渲染管线（FCEngine）

预览和导出共用 `CompositionBuilder`，输入 `Project` 输出：

- `AVMutableComposition`：
  - 主视频使用 **A/B 两条视频轨交替放置片段**，使转场处两段可同时取帧。
  - 一条**基底轨**：插入一段内置生成的 1 秒黑色视频并拉伸铺满总时长，保证每一时刻合成器都会被调用（图片片段、空白处也能渲染）。
  - 原声音频 A/B 两条轨；音乐每段一条轨（或复用）。
  - 变速通过 `scaleTimeRange` 实现；播放与导出均设置 `audioTimePitchAlgorithm = .spectral` 保持音调。
- `AVMutableVideoComposition`：`customVideoCompositorClass = MetalCompositor`，指令按时间分段，每段指令描述该时间内的图层（来源轨或图片、变换、滤镜参数、转场类型与进度）以及字幕。
- `AVMutableAudioMix`：每条音频轨的音量、淡入淡出用 volume ramp 表达。

`MetalCompositor`（实现 `AVVideoCompositing`）：
- 源帧 `CVPixelBuffer` 通过 `CVMetalTextureCache` 零拷贝转为 `MTLTexture`。
- 每帧步骤：每个图层 → 变换（fill 画幅 + 用户缩放位移旋转）→ 滤镜（调节参数 + 3D LUT 预设，单 pass）→ 若在转场中，两图层由转场 shader 混合 → 叠加字幕纹理 → 写入输出 pixel buffer（来自 `renderContext` 的池）。
- 图片素材在合成器内加载为纹理并缓存。
- 字幕：Core Text 渲染为纹理，按（文字 + 样式 + 输出尺寸）缓存。
- 滤镜预设使用程序生成的 3D LUT（33³），以后可接入 .cube 文件。

预览：`AVPlayer` + `AVPlayerItem(composition)`，视图使用 `AVPlayerLayer`。工程变化时防抖重建 player item 并恢复播放头位置。拖动播放头时用 `seek(toleranceBefore: .zero, after: .zero)`。

导出：`AVAssetExportSession` 不支持自定义码率 / 编码灵活度，因此用 `AVAssetReader`（读合成后的视频与混音输出）+ `AVAssetWriter`（H.264 / HEVC 硬件编码）。进度、取消通过异步任务实现。

### 4.4 素材（FCMedia）

- 探测：`AVURLAsset.load(.duration, .tracks…)`、图片用 ImageIO 读尺寸与方向。
- 缩略图：`AVAssetImageGenerator` 按时间线缩放级别生成，内存 + 磁盘缓存，只生成可见范围。
- 波形：`AVAssetReader` 读 PCM，降采样为峰值数组，缓存到工程 `cache/`。

### 4.5 字幕识别（FCTranscribe）

- 协议 `Transcriber`：输入音频文件 URL，输出带时间戳的片段。
- 实现 `WhisperKitTranscriber`：默认模型 `openai_whisper-small`（中文效果与速度平衡），首次使用下载到 `~/Library/Application Support/FrameCut/Models`，显示下载与识别进度。
- 流程：从主轨导出一段混好的 16kHz 单声道音频 → 识别 → 把结果时间映射为时间线时间 → 生成字幕条（覆盖已有自动字幕前需确认）。

### 4.6 界面（App）

布局对标剪映：

```
┌──────────────┬─────────────────────────┬──────────────┐
│ 素材 / 音乐   │        预览播放器         │  属性检查器   │
│ 转场 / 滤镜   │  （画幅框、时间、播放控制） │（随选中对象变） │
│ 字幕（标签页） │                         │              │
├──────────────┴─────────────────────────┴──────────────┤
│ 工具条：撤销 重做 分割 删除 | 缩放                      │
│ 时间线：时间尺 / 主视频轨（缩略图）/ 音乐轨（波形）/ 字幕轨 │
└────────────────────────────────────────────────────────┘
```

- 深色主题，强调色单一。
- 时间线用 SwiftUI `Canvas` 自绘轨道与片段，只绘制可见范围；缩略图以图片块叠加。
- 启动窗口：最近项目列表 + 新建按钮。

## 5. 风险与对策

| 风险 | 对策 |
|---|---|
| 自定义合成器在空白时间段不被调用 | 基底黑色轨铺满全时长 |
| 转场重叠导致 A/B 轨计算复杂 | 布局集中在 `TimelineLayout` 纯函数，单元测试覆盖 |
| 工程变化频繁重建 player item 造成卡顿 | 防抖 + 仅在编辑结束时重建；属性调节（滤镜参数）通过合成器共享参数实时生效 |
| WhisperKit 下载 / 编译失败 | `Transcriber` 协议隔离；失败时提示，不影响其他功能 |

## 6. 测试

- FCCore：时间线布局、分割 / 删除 / 修剪 / 变速 / 转场约束、撤销重做、工程编解码 —— 单元测试。
- FCEngine：用 ffmpeg 生成的测试素材，构建合成并导出短视频，校验时长、分辨率、帧可读 —— 集成测试。
- 手动验收：用一条真实 3 分钟素材走完整闭环。

## 8. HDR 支持（2026-10-16 追加）

作者要求：HDR 是基本能力，必须完整支持。iPhone 12 起默认录制杜比视界（HLG 兼容），是主要素材来源。

### 目标

- 识别 HLG、PQ（HDR10）、杜比视界（按 HLG 底层处理）素材，素材与片段显示 HDR 标记。
- 工程色彩模式：SDR / HDR。导入第一条 HDR 素材时自动切到 HDR（用户手动设置过则不再自动切换）。
- 全链路 10 位以上：解码 10 位，Core Image 半精度浮点、扩展线性工作空间（1.0 = 203 尼特参考白，BT.2408），不截断高光。
- HDR 预览：HDR 工程以 HLG 输出到播放器，支持 EDR 的屏幕显示真实亮度。
- 导出：HDR 工程可选 HDR HLG（默认）、HDR10（PQ）、SDR（色调映射）；HDR 导出强制 HEVC Main10 并写正确色彩标记。
- SDR 输出时对 HDR 内容做色调映射（高光平滑压缩、参考白约 0.85、峰值 1000 尼特映射到 1.0），不截断。
- 滤镜与调节：HDR 工程在 HLG 感知空间里调色（覆盖到 1000 尼特），SDR 工程在 sRGB 空间。亮度 / 对比度 / 饱和度 / 色温并入同一张 LUT。
- SDR 素材、照片、字幕在 HDR 工程中位于参考白（1.0），不刺眼。

### 非目标

- 按素材实际峰值自适应的色调映射（统一按 1000 尼特峰值）。
- 广色域软映射（BT.2020 → 709 采用 Core Image 默认转换）。

### 架构

- 输出动态范围 `DynamicRangeOutput { sdr, hlg, pq }` 决定：合成器类（输出像素格式：SDR 为 BGRA，HDR 为 64RGBAHalf）、视频合成色彩属性、渲染目标色彩空间。
- 每帧流程：源（若工程为 SDR 且源为 HDR → 色调映射）→ 填充与变换 → 调色 LUT（HDR 工程用 HLG 空间）→ 转场 → （若工程 HDR 而输出 SDR → 整帧色调映射）→ 字幕 → 按输出色彩空间渲染。
- 色调映射以 65³ LUT 实现（PQ 空间，覆盖 0–10000 尼特），macOS 14/15 行为一致，可测试。
- 工程文件新增字段以 decodeIfPresent 兼容旧文件，`schemaVersion` 不变。
- 实测：HLG 导出由编码器自动生成杜比视界 Profile 8.4 配置（与 iPhone 一致）；HDR10 导出带母版显示与内容亮度元数据。
